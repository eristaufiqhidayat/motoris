1. Cakupan akun harus diingat di tiap query

Stronglocal-substitutable
app/Support/Akses/Akses.php · app/Support/Menu/SumberTabel.php
app/Http/Controllers/TrackingSalesController.php · TrackingKoordinatorController.php
app/Http/Controllers/LapLoadingBarangController.php · MenuController.php
Celah yang terbaca di kode hari ini. Role Koordinator bawaan memegang menu-menu ini lewat RoleBawaan; pengaturan role di database produksi belum diperiksa.
  • TrackingSalesController:30-43 mengembalikan rute GPS motoris mana pun; komentar baris 45 mengakui rute tidak dibatasi cakupan.
  • TrackingKoordinatorController tidak memakai cakupan di ketiga endpoint.
  • LapLoadingBarangController:23 membaca riwayat distributor tanpa cakupan.
  • MenuController:129 menjalankan DB::table($table) untuk tabel tanpa sumber. Tabel lap_* memuat nama sebagai teks, jadi batasiKaryawan tidak bisa dipasang.

Problem

Query baru terbuka sampai penulisnya ingat membatasi. SumberTabel::query() sendiri berbunyi "bila perlu".

Solution

Satu module memegang keputusan "yang boleh dilihat akun ini". Tanpa cakupan menjadi pilihan yang dinyatakan dan bernama.

Wins

  • Leverage: satu aturan, 35 berkas pemanggil
  • Locality: 4 depoCakupan menjadi satu
  • Lenyapnya panggilan statis ke KuotaMotorisController
  • Satu test menyapu semua menu
Sebagian bisa jadi sengaja, misalnya rute GPS tetap terlihat. SumberTandaOutlet memang menyatakan tanpa cakupan. Keputusan per endpoint perlu dibuat sebelum dibatasi. Test tracking sekarang tidak menguji cakupan.

2. Rumus KPI ditulis per layar dan sudah berbeda

Strongin-processlocal-substitutable
app/Support/Motoris/SummaryDepo.php · LaporanMotoris.php · DetailMotoris.php · Dashboard.php
app/Http/Controllers/HomeController.php · TrackingSalesController.php · Mobile/KinerjaController.php
config/mobile.php · resources/js/Support/summaryDepo.js · Pages/Home/partials/metrikBeranda.js

Problem

Motoris yang sama bisa punya IPT berbeda di dua layar, karena EC hanya penjualan di atas minimal_transaksi (PenjualanController:80-81).

Solution

Pindahkan definisi ke satu tempat bernama. Layar hanya merangkai hasil dan menampilkan.

Wins

  • Locality: rumus berubah di satu tempat
  • Lenyapnya Home::kpi dan kpiHari
  • Test rumus tanpa HTTP
Butuh keputusan produk dulu: IPT satu rumus atau dua. Test sekarang mengunci keduanya (SummaryDepoTest:64, DetailMotorisTest:120). DetailMotoris menulis perbedaan hari kerjanya sebagai "sengaja". Ini hanya menyangkut tabel dasar trx_*, bukan lap_*.

3. Tanda aktif dan milik tim punya banyak arti

Stronglocal-substitutable
app/Http/Controllers/HomeController.php (687 baris, 20 method privat)
app/Support/Motoris/KinerjaKoordinator.php · Dashboard.php · SummaryDepo.php
app/Support/Menu/Motoris/SumberLastSeen.php · app/Support/Menu/SumberTandaOutlet.php

Problem

Komentar SummaryDepo:281 menyebut definisinya sama dengan HomeController::tandaMotoris; kode Beranda sudah memakai arti lain.

Solution

Satu module menjawab tanda mana yang terbuka bagi sebuah tim. Controller Beranda melepas aturan ke module itu.

Wins

  • Lenyapnya panggilan statis HomeController::lupakanTanda
  • Locality: arti tanda satu tempat
  • Pasangan admin/koordinator melebur
  • Aturan teruji tanpa HTTP
Perlu dicek berbeda dari Ditandai mungkin memang dua konsep. Beri keduanya nama, jangan dipaksa satu. Istilah Tanda, Cakupan, dan IPT belum ada di GLOSSARY.md.

4. Menu/Show.vue menyimpan perilaku per tabel

Strongin-process
resources/js/Pages/Menu/Show.vue (567 baris)
resources/js/Pages/Menu/partials/* · config/marketama.php

Problem

Tiap perilaku tabel baru menambah cabang di satu halaman. Dalam seminggu angkanya naik dari 5 cabang menjadi 29 rujukan. Bilah filter sudah tergandakan dan berbeda (Show.vue:328-331, 379-383).

Solution

Keputusan "tabel X berperilaku Y" pindah ke config, seperti sumber. Satu module membaca dan merender perilaku itu.

Wins

  • Locality: tabel baru hanya sentuh config
  • Leverage: satu daftar, 9 tabel
  • 5 peta warna status menjadi satu
  • Show.vue akhirnya bisa punya spec
Keraguan 31 Okt soal laju pertambahan drawer sudah terjawab: tetap bertambah. Sebagian drawer tetap one-off, jadi yang digeneralisasi adalah pemilihan drawer, bukan isi drawer.

5. Tanggal lokal dibaca dari kolom UTC

Worth exploringin-process
app/Support/Mobile/Pengaturan.php · app/Support/Menu/JamLokal.php
app/Support/Motoris/Dashboard.php · KinerjaKoordinator.php
app/Http/Controllers/Admin/AkunController.php · RoleController.php

Problem

Bug jatuh di pagi hari dan batas periode, jadi tidak tampak di data siang. Test zona waktu langsung untuk JamLokal dan Pengaturan belum ada.

Solution

Satu cara mengubah tanggal atau rentang lokal menjadi batas UTC dan memformatnya kembali.

Wins

  • Locality: aturan zona di satu tempat
  • Lenyapnya 7 helper privat
  • Batas hari teruji tanpa database
Dampak angka belum diukur. Kebocoran yang sudah terbaca di Dashboard bisa diperbaiki lebih dulu tanpa menunggu refactor ini.
